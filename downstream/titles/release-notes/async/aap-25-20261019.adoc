== Overview

This async release of Ansible Automation Platform 2.5 updates the supported ansible.controller collection in execution environments and the base container images for the Ansible Automation Platform 2.5 operators. It also fixes bugs in the automation controller and the platform operator. The fixes cover OAuth2 token performance, how HostList API errors are handled, and AutomationController reconciliation after an operator upgrade.

== Highlights

* The ansible.controller collection is updated to 4.6.34. (AAP-96260)
* The base container images for the Ansible Automation Platform 2.5 operators are updated, along with kube-rbac-proxy compatibility changes. (AAP-76357)
* Automation controller no longer gets row lock convoys when OAuth2 tokens are used heavily. (AAP-94180)
* Error responses from the HostList API no longer show internal database details. (AAP-90885)

== Bug fixes

=== Controller
* Fixed an issue where heavy use of OAuth2 tokens caused a row lock convoy. (AAP-94180)
* Fixed an issue where the HostList view caught all exceptions and returned the raw exception message in the HTTP 400 response. Crafted host_filter query parameters, such as credential__search=x, could trigger Django FieldError or database-level exceptions. Their messages could expose schema details and raw PostgreSQL errors to the caller. RuntimeError messages from known SmartFilter parse failures are still returned to the caller. All other exceptions are now logged on the server and return a generic "Invalid host filter." message. SmartFilter.BoolOperand._expand_search now also checks that the search relation is a real Host model field, and raises a ParseException if it isn't. (AAP-90885)

=== Platform operator
* Fixed an issue where AutomationController could fail to reconcile after an operator upgrade. (AAP-93806)
