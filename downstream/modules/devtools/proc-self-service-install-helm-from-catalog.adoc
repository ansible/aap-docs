= Configure the {SelfServiceShort} Helm chart from the OpenShift catalog

.Prerequisites
* You have created a project for {SelfServiceShort} in {OCPShort}.
* You have created secrets in {OCPShort} for {PlatformNameShort} authentication.
* If you configure SCM integration (for example, importing from private repositories or using templates that access SCM), you have created secrets in OpenShift for SCM authentication.

* You have completed the plug-in delivery prerequisites:
** For OCI container delivery (default): You have created the `<release-name>-dynamic-plugins-registry-auth` secret.
** For HTTP plug-in registry (deprecated override): If you are overriding the default OCI delivery to use an in-cluster HTTP plug-in registry, you have deployed the plug-in registry and plan to set `pluginMode` to `tarball`.

.Procedure
. In the {OCPShort} web console, select the *Developer* view.
. Select your project and click the btn:[Helm] option in the OpenShift sidebar.
. Click btn:[Create] and select *Helm Release*.
. Search for `Portal` in the Helm Charts filter, and select the `Automation Portal` chart.
. Click btn:[Create] and select the *YAML view*.
. Update the `clusterRouterBase` value with the base URL of your OpenShift instance.
+
[IMPORTANT]
====
You must replace the default `apps.example.com` placeholder value. If the default value remains, Helm chart validation fails.
====
+
----
redhat-developer-hub:
  global:
    clusterRouterBase: apps.example.com
----
. Configure the plug-in delivery mode and version by setting the `imageTagInfo` key:
+
The Helm chart defaults to OCI container delivery (`pluginMode: oci`). Set `imageTagInfo` to the plug-in version from the Helm chart or the lifecycle page. To override the default and use the deprecated HTTP plug-in registry, set `pluginMode` to `tarball`.
+
----
redhat-developer-hub:
  global:
    pluginMode: oci
    imageTagInfo: "<plugin-version>"
----
. Set the {PlatformNameShort} organization to synchronize. The default value is `Default`. Update the `orgs` key to match your organization name:
+
----
redhat-developer-hub:
  upstream:
    backstage:
      appConfig:
        catalog:
          providers:
            rhaap:
              '{{- include "catalog.providers.env" . }}':
                orgs: "<your-aap-organization-name>"
----
. *Optional:* Update the `CUSTOMER_SUPPORT_URL` to point to your support portal:
+
----
redhat-developer-hub:
  upstream:
    backstage:
      extraEnvVars:
        - name: CUSTOMER_SUPPORT_URL
          value: https://access.redhat.com/support
----
. Click btn:[Create].
